# Design: markdown-viewer

## Context

medit は Markdown 専用の閲覧ツールとして新規に実装する（グリーンフィールド。既存コードなし）。言語は Go。編集機能は自前実装せず、外部コマンドの vi（または `$VISUAL` / `$EDITOR`）へ委譲する。閲覧（レンダリング表示）→ `e` で vi 編集 → 終了で閲覧へ復帰、という往復が中核の UX。利用文書は日本語を含むため、CJK の折返し・表示品質が重要。

前提となる要求は `proposal.md`、振る舞いの詳細は `specs/*/spec.md` を参照。

## Goals / Non-Goals

**Goals:**

- `medit <file.md>` で起動する単一バイナリの Markdown Viewer
- Glamour によるフルレンダリング（CommonMark + GFM の表・取り消し線、端末幅での折返し）
- vi / less 風のスクロール操作と、`e` による外部エディタ往復・自動再読込
- 日本語文書の表示品質（折返し・桁崩れなし）
- コアロジック（ファイル読込・レンダリング・位置変換）を TUI から分離し `go test` で検証可能にする

**Non-Goals:**

- 自前のテキスト編集機能（挿入モード・バッファ編集・undo 等）— vi に委譲
- ライブプレビューや分割ペイン編集（将来、別の変更として検討）
- Viewer 内検索（`/`）・見出しジャンプ（TOC）・複数ファイルのブラウズ
- fsnotify によるファイル変更の自動検知（復帰時 + `r` のみ）
- 設定ファイル・キーカスタマイズ、Windows 対応（vi 前提のため Unix 系のみ）

## Decisions

### D1: TUI フレームワークは Bubble Tea + bubbles/viewport

- **理由**: Elm アーキテクチャで状態管理が単純になり、スクロール表示は公式コンポーネント bubbles/viewport をそのまま使える。外部プロセス起動（D3）が公式サポートされている点も決定的。
- **代替案**: tcell 直接利用（低レベルすぎる）、tview（viewer 用途には可だが ExecProcess 相当の枠組みがない）。

### D2: レンダリングは Glamour のフルドキュメントレンダリング

- **理由**: 編集を持たないため、ソース行と表示行の対応維持という制約が消え、既製のフルレンダリングをそのまま使える。表・折返し・シンタックスハイライト付きコードブロックまで得られる。
- スタイルは自動選択（ダーク / ライト検出）、レンダリング幅は端末幅に追従し、リサイズ時と内容変更時のみ再レンダリングする（キー操作ごとには再レンダリングしない）。

### D3: 外部エディタ起動は `tea.ExecProcess`

- **理由**: TUI の一時停止（alt screen 離脱・termios 復元）→ 子プロセスへの端末譲渡 → 終了後の復帰とメッセージ配送までを Bubble Tea が公式にサポートする（less の `v` キーと同じ確立されたパターン）。
- エディタ解決は `$VISUAL` → `$EDITOR` → `vi`。環境変数は空白でフィールド分割し、先頭をコマンド、残りを引数として扱う（shell は経由しない）。
- 起動引数は `+N <path>`（N は表示位置に対応する近似ソース行、D4）。エディタが非 0 終了しても Viewer は復帰し、メッセージ表示のうえ再読込は実行する。

### D4: 表示位置とソース行の対応は割合ベースの近似

- レンダリング行 ↔ ソース行の厳密な対応表は持たない（Glamour が提供しないため）。
- `vi +N` へ渡す N は「viewport のスクロール割合 × ソース総行数」の近似で算出する。復帰後のスクロール位置は、レンダリング済みテキスト上のオフセットを維持し、内容が短くなった場合はクランプする。
- **代替案**: 見出しアンカーによる対応付け — 精度は上がるが MVP には過剰。将来の改善余地として残す。

### D5: パッケージ構成 — コアと TUI の分離

```
cmd/medit/          main: 引数処理、Bubble Tea 起動
internal/loader/    ファイル読込（UTF-8）、新規ファイル扱い、再読込
internal/render/    Glamour ラッパ（幅指定・スタイル選択）、スクロール割合→行番号の近似変換
internal/ui/        Bubble Tea の Model/Update/View、viewport、キーマップ、ExecProcess 統合、ステータスバー
```

- `loader` / `render` は端末非依存の純粋 Go パッケージとしてユニットテストする。`ui` は薄く保つ。
- モジュールパスは `github.com/sudabon/medit`。

### D6: CJK 表示

- 本文の折返し・幅計算は Glamour（内部の reflow / ansi）に委ね、日本語文書での品質を検証タスクで確認する。ステータスバーの切り詰めなど自前描画部分は `go-runewidth` で幅計算する。IME 入力の処理は不要（入力は vi 側の責務）。

### D7: 開発基盤

- `go vet` + `golangci-lint` + `go test` を最小構成で整備し、GitHub Actions（push / PR で test + lint)を 1 ワークフロー追加する。

## Risks / Trade-offs

- [Glamour の日本語折返し・全角幅処理に癖がある可能性] → 日本語文書での表示検証を必須タスクにする。問題があればレンダリング幅の調整・スタイル設定で回避し、それでも不足なら該当ブロックのみ自前整形に切り替える
- [`+N` 近似のズレ] → MVP では近似で許容（開く位置が数行ずれても実害は小さい）。将来は見出しアンカー方式で精密化可能
- [端末による alt screen / termios 復帰の挙動差] → Terminal.app / iTerm2 / WezTerm での vi 往復の手動確認をタスク化する
- [大きなファイルの再レンダリング時間] → 再レンダリングを幅変更時と内容変更時に限定。通常サイズの文書を対象とし、巨大ファイル対応は将来課題
- [`$EDITOR` に複雑なコマンドライン（クォート含む）が設定されている場合] → フィールド分割の単純解釈とし、対応範囲を README に明記する

## Migration Plan

新規実装のため移行はなし。ロールバックは git revert で足りる。旧変更 `vi-style-markdown-editor` は未実装のまま本変更で置き換える（ディレクトリは残置、不要時に削除）。
